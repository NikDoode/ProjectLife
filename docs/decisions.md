# Architectural Decisions

## 2026-07-21

### TreeView вынесен в отдельную View

Причина

Дерево является одним из представлений предметной модели, а не центральной частью приложения.

Следствие

App больше не зависит от конкретной реализации дерева.

---

## 2026-07-21

### Projection отделена от View

Причина

Backend отвечает за преобразование данных.

Frontend отвечает за их отображение.

Следствие

Backend не знает о React.

## 2026-07-21

### Добавлен минимальный View Framework

Причина

Приложение должно поддерживать несколько представлений одной предметной модели, а `App` не должен зависеть от конкретной реализации дерева.

Решение

Добавлен `ViewRenderer`, который выбирает реализацию представления по `viewType`.

Сейчас поддерживается только `tree`.

Следствие

Новые View можно будет подключать без прямого импорта их компонентов в `App`.

Ограничение

Пользовательский переключатель представлений пока не реализован.

# ADR-001

## Один объект — много представлений

Дата:
2026-07-23

Решение:

Объект существует только один раз.

TreeView,
SpatialView,

Причина:

Избежать синхронизации копий.

# ADR-002

## Настройки отображения не входят в Item

Дата: 2026-08-05

Решение:

Координаты, размер и цвет пространственного узла хранятся отдельно от предметного объекта. Настройки всего представления — тема, сетка, линии, отображение выполненных и архивных объектов — также хранятся отдельно.

На этапе 007 эти данные сохраняются во frontend в ключах `projectLife.nodeDisplay.v1` и `projectLife.workspacePrefs.v1` в `localStorage`.

Причина:

Положение и оформление описывают конкретное представление, а не предметную сущность. Это сохраняет возможность показывать один `Item` по-разному в Tree View, Spatial View и будущих представлениях.

Следствие:

Изменение оформления узла не вызывает запросов к backend и не меняет схему SQLite. Синхронизация настроек между браузерами пока отсутствует.

# ADR-003

## Ограниченная персонализация Spatial View

Дата: 2026-08-05

Решение:

Spatial View поддерживает свободное перемещение узлов, автоматическую начальную раскладку и сброс координат. Размер выбирается из трёх фиксированных вариантов: 56, 110 и 170 px. Цвет выбирается из восьми предустановленных вариантов, тема — из пяти готовых палитр.

Для скрытия архивных объектов на текущей модели используется статус `cancelled`.

Причина:

Ограниченный набор настроек позволяет персонализировать карту без введения универсального конструктора, произвольного изменения размеров или изменений предметной модели.

Следствие:

Размеры и цвета остаются предсказуемыми, новые объекты получают автоматическое положение, а ручная раскладка восстанавливается после перезапуска браузера.

# ADR-004

## Рабочее пространство является самостоятельной проекцией объектов

Дата: 2026-08-06

Решение:

Рабочее пространство хранит собственные правила отображения объектов и собственные placements, включающие координаты, размер и цвет узла. Правила ссылаются на существующий `Item` и задают один из режимов: только объект, объект с непосредственными детьми или всё поддерево.

Системное пространство «Общее» не ограничивает набор объектов. На текущем однопользовательском этапе пространства сохраняются во frontend в `projectLife.workspaces.v1`.

Причина:

Один предметный объект должен присутствовать в нескольких пространствах без создания копий и иметь независимое пространственное оформление в каждом из них. Хранение правил позволяет автоматически учитывать новые элементы дерева.

Следствие:

`Item` и его иерархия не зависят от рабочих пространств. Переключение пространства изменяет только состав и оформление проекции. Созданный объект остаётся общей предметной сущностью и при необходимости получает отдельное правило включения в активное пользовательское пространство.

# ADR-005

## Relation является отдельным слоем связей между Item

Дата: 2026-08-08

Решение:

Каноническая иерархия продолжает храниться в `Item.parent_id`. Дополнительные и смысловые связи хранятся в отдельной сущности `Relation` с направленными `source_id` и `target_id`.

Дополнительное родительство представлено типом `parent_of` и не создаёт копию `Item`. Типы `depends_on`, `blocks` и `related_to` образуют первый расширяемый набор смысловых связей.

Область действия определяется nullable-полем `workspace_id`: отсутствие значения означает глобальную связь, значение идентификатора — локальную связь Workspace. Отдельное сохраняемое поле `scope` не используется.

Для устойчивой ссылки локальных связей Workspace получает минимальную backend-идентичность. Правила присутствия, координаты и визуальные настройки по-прежнему хранятся во frontend.

Причина:

Один объект должен отображаться в нескольких структурных и смысловых контекстах без превращения канонического дерева в DAG и без дублирования предметных данных. Nullable `workspace_id` исключает противоречие между отдельным признаком области действия и фактической привязкой к пространству.

Следствие:

`GET /items/tree` остаётся канонической проекцией. Tree View и Spatial View дополняют её данными Relation. Структурные циклы запрещены только для `parent_of`; смысловые связи могут образовывать произвольный граф.
